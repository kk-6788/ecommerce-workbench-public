# TypeSafe 第一阶段：影子审核

2026-09-19

## 已实现

本轮把 TypeSafe 从“只保存 Key”接到商品审核业务。实现两个场景：

- 证据支持：待核对卖点是否由选定来源明确支持，以及来源是否适用于指定商品/SKU。
- 关键词：购买、比较、使用咨询、其他或资料不足；从已有分类中选择候选，没有匹配选择 NONE。分类不改写词库和业务统计。

新增“AI 辅助审核”页面，具备来源选择、审核方案、发送资料预览、独立内容/费用审批、持久任务提交、原始结构化判断、用量、人工审核历史、补证据复查及站内通知。

代码使用 TypeSafe 官方 `POST https://api.typesafe.ai/v1/systemone` 合同，不安装新 SDK、不自动重试。执行复用现有队列、租约、方案 hash、审批及费用账本。响应按 Choice 完整分布和原始置信度校验，拒绝缺答案、额外问题、布尔数值、NaN、字符串百分数或不完整概率分布。

## 怎样操作

1. 在“服务连接”填写自己的 TypeSafe Key 和模型 ID。Key 留在本机私有加密存储，不放入方案或备份。
2. 在“商品档案”建立商品和证据。证据内容需要登记可核对的原文，单有网址不够；本轮不会自动爬取网页。
3. 在“AI 辅助审核”选择商品、场景、卖点、SKU 或关键词，勾选来源，再建立方案。建立方案不会调用模型。
4. 展开记录，检查准备发送到远端的全部文本，去除个人资料和无关商业信息。明显 Key、密码或个人联系方式会被拒绝，仍需人工检查未被规则识别的敏感内容。
5. 内容与费用分别审批。执行前还必须满足下节的真实服务条件；不能通过填写一个金额自行解除费用门禁。
6. 将来真实执行可用后，结果展示在同一审核记录中；人工处理必须填写理由。AI 和人审不会把供应商说法变成已核实事实，也不会批准素材、上架或投放。
7. 补证据后点击“编辑资料后复查”，在表单中重新勾选最新来源、修改卖点，建立新的复查方案。旧批准不迁移。原请求结果/账单未知时不能重复发起。

## 当前真实执行边界

**代码流程已接通并完成本地模拟验证，但生产真实收费执行仍关闭。**

核对的官方 API 文档提供 typed answers 与 token usage，没有单次金额硬上限、已确认的账单查询或可据此结算的费用回执合同。本轮没有核验账户价格、失败收费口径、实际账单，也没有发起真实 TypeSafe 请求。

因此生产 adapter 保持 UNVERIFIED、hard_cap_supported=false。点击提交会明确阻止，不创建已收费的执行假象。后续需要取得服务商可执行的费用限制与核算依据，再实施和验证该费用能力；不能仅修改 VERIFIED 标志或把用户填写的预算当成供应商已经限制收费。若服务商确实不支持所需控制，需要先明确调整产品费用约束，不能悄悄绕过。

即使模型结果成功返回，token 用量也不等于钱款回执：判断结果可保留，但费用继续 UNKNOWN/待核对，不编造 provider_request_id、现金金额或账单。没有查询能力时走本人核对路径。

## 规则与数据安全

- 固定 SHADOW；未实现 AUTO 发布、自动门禁或真实校准资格启用。货源匹配、文案审核、语义评分、经营复盘四个 AI 场景尚未接入。
- <80% 人工必审；80% 至 <95% 建议复核；>=95% 也只是影子建议。FAIL 仍需复核；INSUFFICIENT 始终待补证据。分档使用未舍入值，不平均多个问题的置信度。
- 商品、证据最新修订、候选分类、问题/规则版本、Key/模型变化或 24 小时过期后，旧结果 STALE。当前版本的 KILL 预测阻止检查与人工通过。
- 网络调用不占数据库写锁；在途不能人工终审；迟到结果保留但不应用。超时不重发，重试需要新的方案与审批。
- AI 记录、审批、通用方案/任务/回执接口与页面按 Key 所属用户检查权限。此隔离不代表整个平台业务档案已成为多人 SaaS。
- 已读通知不等于已解决；补证据通知可以重新打开。人工事件只追加，版本冲突返回 409。
- 新增 005 数据迁移及 5 张审核相关表。校准表仅预留记录位置，本轮没有产生校准数据或自动通过资格。

## 验证与回退

新增针对实际业务的自动测试覆盖：审批→worker→HTTP 模拟→审核结果→人审，费用未知、幂等、密钥竞争、用户隔离、源资料修订、复查、通知、置信度边界、畸形响应、超时、KILL、备份与不可变快照。

独立复核发现的隔离、来源修订、在途人工结论覆盖及密钥竞争问题已修复并补回归。最终实际测试数量见交付的测试日志，不以模拟调用代替真实渠道验收。前端已完成 JavaScript 语法与服务端页面测试，尚未进行真实浏览器逐项点击验收。

升级前先备份原数据库。回退源代码不能删除新表和人审历史；旧版备份须使用对应版本的恢复工具恢复到新目录，再升级迁移，不能覆盖升级后产生的业务数据。

接口依据：[官方 HTTP API](https://docs.typesafe.ai/api)、[Choice](https://docs.typesafe.ai/primitives/choice)、[引用核对示例](https://docs.typesafe.ai/cookbooks/citation_check)。阈值是本项目初始策略，不是服务商效果保证。
