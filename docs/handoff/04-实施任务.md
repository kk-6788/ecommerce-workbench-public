# 电商作业平台 Implementation Plan

**Goal:** 以本机低成本工作台完成3–5件/周宠物优先商品的选品、图、视频、确认执行和复盘。

**Architecture:** 单用户网页＋SQLite＋独立worker。资料、预测、审批与外部回执可追溯，真实连接器按能力逐个验证。

**Tech Stack:** Python 3.11、FastAPI、Jinja2、SQLite、Pillow、现有FFmpeg；依赖先盘点后申请安装。

本文件是待执行任务清单，所有任务初始NOT_STARTED。先取得用户“按本包搭建”的实施指令；本次制作规划不构成实施授权。可以单agent顺序执行；需并行时遵守宿主授权和文件所有权，不强制启用子agent。

## 工作协议

相对路径均相对于应用根目录。原始代码仅有占位文件，不存在以下模块和测试；由接手agent按任务创建。

每项拆成可检查的小步：①写该行为的失败测试；②运行指定文件，确认失败是缺实现；③最小实现；④原命令通过；⑤记录证据与状态。环境/文档盘点无需人为造失败。不要写只复述实现的测试。复杂项按表中用例逐个推进，不声称一项只需几分钟。

统一验证命令是 `python -m pytest <表中测试文件> -q`；预期该文件全部用例通过且不访问真实网络。实际测试数以运行结果为准。业务测试均使用临时数据目录，不碰runtime或旧库。真实接入另走T26–T28，不能混入默认pytest。

每项完成更新work/implementation-status.json：task_id、status、changed_files、command、exit_code、evidence_paths、blocker、next_step。状态为NOT_STARTED/IN_PROGRESS/PASSED/BLOCKED；BLOCKED必须说明缺什么及仍可继续的任务。不得无授权自动安装、消费或外部发布。提交遵守用户当前要求和仓库权限；不自动push。

## 关键验收测试示例（待实现接口）

以下是可复制的测试契约，不是声称应用已经存在。T07实现函数签名后运行：

```python
from decimal import Decimal as D
from app.domain.economics import legacy_margin

def test_legacy_margin_preserves_precision():
    assert legacy_margin(price=D('34'), procurement=D('10.45')) == D('14.46')

def test_missing_procurement_is_unknown():
    assert legacy_margin(price=D('34'), procurement=None) is None
```

实现时明确默认commission=D('0.055'), refund_proxy=D('0.08'), freight=D('4'), packaging=D('0.5')；输入无效或价格≤0返回领域校验错误，缺失返回None，不能混用。

T13必须模拟这条时序：已批准plan→提交一次→供应商已接受但本地超时→应用重启→再按执行→返回原attempt且供应商submit_count仍为1→查询成功回执。另测两并发线程提交同plan仍为1。仅测HTTP返回200不足以通过。
