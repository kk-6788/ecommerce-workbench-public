# Validation and Experiment Design

## Objective

Resolve the most important uncertainty before major investment.

Do not validate what is easiest.

Validate what is most dangerous to be wrong about.

---

# 1. Assumption Types

- Problem
- Demand
- Product
- Willingness to pay
- Price
- Channel
- Supply
- Margin
- Retention
- Scale

Prioritize assumptions with:

High importance  
+ High uncertainty  
+ High failure impact

---

# 2. Validation Methods

From lighter to heavier:

- Existing behavioral data
- User interviews
- Review mining
- Search / marketplace analysis
- Survey
- Landing page
- Ad test
- Fake door
- Prototype
- Sample
- Concierge test
- Wizard-of-Oz
- Preorder
- Deposit
- Marketplace listing
- Small-batch inventory
- Paid pilot
- A/B test
- Full launch

Prefer the lowest-cost method that can produce decision-quality evidence.

---

# 3. Experiment Card

Every test should include:

## Hypothesis
What must be true?

## Risk
What happens if it is false?

## Test
What will we do?

## Audience
Who will be tested?

## Metric
What will be measured?

## Success Threshold
What result supports continuing?

## Failure Threshold
What result means stop or redesign?

## Cost Cap
Maximum acceptable spend.

## Time Cap
Maximum test duration.

## Decision
Scale / Keep / Improve / Kill.

Use `../templates/experiment-card.md`

---

# 4. MVP Rule

MVP is:

> Minimum product required to test the core value hypothesis.

Not:
> Cheap-looking final product.

For every feature ask:

> Can the core hypothesis still be tested without it?

If yes, remove or postpone it.

---

# 5. Anti-Patterns

Avoid:

- Launch and see
- No pre-defined threshold
- Changing the metric after results arrive
- Testing multiple critical assumptions in a way that cannot distinguish causes
- Using likes or survey interest as substitute for payment
- Scaling before learning
