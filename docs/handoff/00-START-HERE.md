## 核心目标

给 KK 本人使用的 Windows 本地网页工作台，宠物铺货优先，每周推进3–5个新品：

采集 → 关键词机会 → 商品/规格/货源核验 → 选品 → 主图/SKU图/详情图 → 上架与新品启动 → 短视频成片 → 确认后发布 → 经营结果与可能原因复盘 → 模型校准提议。

- 当前选品按9月14日v4.2.2勘误3；未来研发按9月13日三条腿框架，分模式。
- PM Decision OS v1.2 的方法和模板必须保留并增量扩充；它不是已有程序。
- 系统自动准备，用户确认具体外部动作后执行；**每一笔费用单独审批**。
- 不增加服务器/云存储费用；电脑关闭不要求继续运行。手机局域网为次要入口。
- 图片要可上架，视频要到可发布成片；只有脚本、演示数据或导入功能不算完整交付。

## 必须区分的完成等级

| 等级 | 可以声称什么 |
|---|---|
| G0 | 环境和材料清点完成，依赖批准状态清楚 |
| G1 | 核心算法、数据、审批、任务的离线测试通过 |
| G2 | 本地UI和模拟服务的完整流程通过，明确标“模拟” |
| G3 | 指定平台的真实只读采集和数据口径已验证 |
| G4 | 经确认完成真实图/视频制作、上架/发布和执行结果核验 |
| G5 | 实际经营观察期结束，结果与原因分析可回查 |

G1/G2不能冒充G3/G4/G5。没有新增真实订单数据时仍可完成软件部分，但经营学习处于“待数据”，不是已验证有效。
