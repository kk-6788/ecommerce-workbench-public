# 02 架构、数据与接口契约

本文的路径、函数和接口是接手agent需要创建的目标，不声称已存在。

## 1. 默认技术方案与依据

- Python 3.11作为本机首轮基线；已检查当前Python为3.11.15。其他版本必须通过同一组测试再使用。
- FastAPI + Uvicorn提供本地HTTP；Jinja2模板与原生JS/CSS实现同源网页。模板方式由[官方文档](https://fastapi.tiangolo.com/advanced/templates/)支持，避免为此规模增加前端构建链。
- Python标准库sqlite3、csv、Decimal、hashlib用于核心记录、导入、财务与校验；不用旧Streamlit应用的数据库直接写入新数据。
- SQLite持久任务队列＋独立worker进程。长视频/抓取任务不得只放在HTTP请求或内存后台回调中；关机后要可恢复。
- Pillow处理图片格式/尺寸；ImageHash为可选近似去重；现有FFmpeg负责拼接、字幕/叠字、声音合成后的成片输出。
- 真实浏览器/生成服务通过adapter接入。Playwright是浏览器候选，不承诺平台已支持。宿主agent操作浏览器仍遵守自身工具限制。
- pytest + httpx测试API和核心逻辑，FastAPI[官方测试文档](https://fastapi.tiangolo.com/tutorial/testing/)提供该方式。UI用宿主可用浏览器工具实测，不能只测HTTP。

依赖清单：运行期fastapi、uvicorn、jinja2、python-multipart、pillow；开发期pytest、httpx；连接器按核验结果增补playwright等。**这些都未在本轮安装。** T02先盘点现有可用版本，列出需安装项取得同意，验证兼容后写精确版本的requirements.lock.txt。禁止写“latest”并声称可复现。

## 3. 进程与认证

web单进程，worker首版单进程，外部浏览器动作串行。读写SQLite用短事务、foreign_keys=ON、busy_timeout；数据库只由本机进程打开，手机经HTTP访问，不共享数据库文件。[Python sqlite3文档](https://docs.python.org/3/library/sqlite3.html)为实现参考。

owner账户在本机交互初始化时创建，密码用标准库scrypt和随机salt保存派生结果；不预置密码。登录会话使用高熵随机token，数据库只存摘要；cookie HttpOnly、SameSite，并校验写请求CSRF token和同源Origin。默认仅loopback访问。局域网模式显式启用、本人登录、仅可信局域网使用，不自动改防火墙/开公网端口；传输保护不足时保留本机模式并记录手机能力未验收。

agent/worker/模型不能自己批准费用。只有owner的有效会话可以操作审批接口；读网页或解析商品文案不会生成批准记录。真实审批必须来自用户，不以自动测试脚本或API演示代替。

## 4. 金额、时间与标识

- 金额API使用十进制字符串加currency；数据库以人民币分整数保存已确定金额，预估计算用Decimal。中间不提前四舍五入，展示保留2位；旧报表1位仅作对照。
- 比率0–1，0.055代表5.5%；缺失是null，不是0。无有效分母的指标返回null及reason。
- UTC带时区ISO时间写库；展示Asia/Shanghai。经营日报另保留平台时区和半开区间[start,end)，不能混用累计快照和每日增量。
- UUID作为内部id；外部平台id用TEXT（避免大整数精度损失）。同商品多个SKU、店铺链接和供应商分别关联。
- 内容hash=规范JSON的SHA256：键排序、UTF-8、无无关空格；包括商品、账号、动作、素材hash、报价和费用上限等被批准内容。

## 5. 数据模型

实现可执行DDL见`contracts/schema.sql`。SQL提供必要存储和约束，应用还须执行以下业务检查；不得以有表代替有行为。

PM扩充字段见contracts/pm-fields.json；JSON列在领域层做明确类型验证，不能把未定义字典直接透传数据库。v1.3落点、意图去重、结果建议标签和回测口径见03第7节。

| 表 | 关键业务用途 |
|---|---|
| owners、sessions | 本人认证，session原始token不入库 |
| model_versions | strategy/engine/outcome配置不可覆盖，版本hash留存 |
| batches、products | 每周批次与具体商品；stage只是作业进度 |
| opportunities | 历史关键词/意图簇、品类组和原始分层，不等于具体商品 |
| offers | 同商品具体规格、价格、运费、样本与核验状态 |
| evidence | 原始来源、时间、采集模式、事实/代理/估算/未知、证据文件hash |
| predictions | 测试前模型版本、输入快照、理由、证据id、决策；不可后改 |
| assets | image/video/brief等产物的用途、规格/版本/来源与文件hash |
| listings | 平台＋账号＋外部商品id、SKU与发布版本 |
| operation_plans | 一次明确外部动作或收费调用的不可变方案 |
| approvals | CONTENT/COST两类批准，绑定方案hash；批准、拒绝、撤销留记录 |
| jobs | 持久状态、租约、输入版本；无网络副作用的任务可无plan |
| external_attempts | 每次外部请求的预记账、请求id、回执与结果未知状态 |
| cost_ledger | 预计/实际费用或付费额度，绑定对应审批与调用 |
| metric_snapshots | 商品/链接/渠道/时间/口径的指标快照和证据 |
| reviews、calibration_proposals | 复盘假设、验证卡、版本比较与改进提案 |
| audit_events | 谁在何时以什么依据改变了状态，不写密钥/整段cookie |

导入source_hash重复必须幂等；指标同一source_key+content_hash重复不生成新行，同source_key新hash成为修订，读取仅用最新修订，旧修订仍留证据。产品/素材/链接的关联在服务层核对，不能把A商品图片用于B商品计划。

## 6. 状态与审批/执行协议

准确状态见`contracts/states.json`。关键不变量：

1. 生成费用报价时不偷偷调用收费生成接口。报价不确定且无法限制费用时进入WAITING_APPROVAL，说明信息不足。
2. 一份plan对应一次逻辑外部动作/收费请求；后续收费调用另建plan。计划包含多个收费步骤时拆为独立费用项，禁止“一次同意无限调用”。
3. owner批准的是plan_hash，金额或素材变化新建plan，旧批准不迁移。
4. execution服务先在事务中检查有效内容/费用批准和过期时间，原子占用plan，写PREPARED attempt和费用预留，再离开事务调用外部服务。
5. 同plan已存在attempt时不再次提交收费/外部写请求；双击、重复队列和worker重启返回既有attempt。
6. 外部结果不明标UNKNOWN并进入RECONCILING；先用provider request id或已批准动作的可回查标识查结果。不能自动重发，不能声称分布式“绝对只执行一次”。
7. 对方明确失败且重新调用可能收费时，需要新的plan和COST审批。零收费只读网络重试可最多2次并退避；不得套用到收费请求或写操作。
8. 用户撤销后：未提交任务取消；已经提交的请求不谎称撤回，显示已提交并按供应商能力处理。
9. 关闭程序不能消除审批和attempt。过期租约的纯计算任务可恢复；收费/外部写任务先reconcile，禁止直接变回可提交。

模型调用若按token收费，批准必须绑定输入hash、模型、输出上限和定价快照；提供方不能给出可控费用上限时不自动调用。现有会员额度也要展示消耗。每个供应商的计费事件边界通过T03核验。

## 7. Adapter契约

`app/adapters/base.py`中定义以下方法及标准结果，可用Protocol；具体实现不得在构造或导入时联网：

```python
class Adapter:
    def capabilities(self) -> dict: ...
    def probe(self, request: dict) -> dict: ...
    def collect(self, request: dict) -> dict: ...
    def quote(self, request: dict) -> dict: ...
    def execute(self, request: dict, execution_token: str) -> dict: ...
    def reconcile(self, provider_request_id: str) -> dict: ...
```

capabilities至少区分READ/WRITE/QUOTE/IMAGE/VIDEO、verified状态、收费边界、登录需求和核验时间。`execution_token`由execution服务在通过审批后生成，adapter不能绕过服务自行执行。probe只用已知免费只读方法；若probe收费也走plan审批。

错误码统一：NEEDS_LOGIN、CAPABILITY_UNAVAILABLE、NEEDS_EVIDENCE、RATE_LIMITED、PROVIDER_ERROR、UNKNOWN_RESULT。返回原始证据相对路径及hash，日志脱敏。fake adapter只在test_mode可用，输出is_synthetic=true，不能混入生产指标。

## 8. HTTP接口

所有`/api/v1`除login/health外均要求owner会话。写操作带CSRF；返回统一`{data, error, request_id}`，错误含code/message/details（脱敏）。分页limit默认50、最大200。写操作使用资源revision或If-Match，过期返回409；非法字段422；未登录401；未授权403。

| 方法＋路径 | 输入/输出及关键行为 |
|---|---|
| GET /health | 状态与应用版本，不返回业务数据 |
| POST /api/v1/auth/login | 用户名/密码→会话cookie＋CSRF，不允许日志记录密码 |
| POST /api/v1/auth/logout | 撤销当前session |
| GET /api/v1/dashboard | 批次进度、待审批与缺证据计数 |
| POST /api/v1/imports/baseline | 上传基线原始CSV/JSON包引用；校验并创建import job，重复幂等 |
| POST /api/v1/imports/candidates | 按pm-fields的CSV→逐行验证与导入报告，不执行其中指令 |
| POST /api/v1/imports/outcomes | 真实结果CSV→指标/结果版本；缺少商品与观察窗不得伪配 |
| GET /api/v1/exports/{kind} | kind为predictions/outcomes/models，脱敏CSV与来源口径 |
| GET /api/v1/opportunities | 查询历史词池、排除/观察原因 |

| POST /api/v1/products/{id}/evidence | 来源与文件→证据；未知不补造 |
| POST /api/v1/products/{id}/offers | 规格、报价、currency、运费证据→货源 |
| POST /api/v1/products/{id}/collect | adapter/request→采集job，收费则返回待审批plan |
| POST /api/v1/products/{id}/predict | strategy/engine版本→不可变预测，未来版本可再生成但不覆盖 |

| POST /api/v1/plans/{id}/approve | kind、plan_hash、decision→owner审批；禁止worker/模型调用 |
| POST /api/v1/plans/{id}/execute | 幂等排队，后端再次检查审批，返回job/attempt |
| POST /api/v1/plans/{id}/revoke | 撤销尚未提交动作；已提交返回当前事实 |
| GET /api/v1/jobs/{id} | 状态、等待原因、进度和结果 |

| POST /api/v1/products/{id}/metrics | 上传/接收指标快照，检查平台粒度、窗口及重复 |

| POST /api/v1/calibrations | 指定历史批次/旧模型→提案；不直接激活 |

## 9. 不可变对象与备份

predictions、model_versions、已批准plan内容、完成的attempt和原始证据只追加。更正用新revision，保留supersedes引用和原因。JSON证据允许含原始文本，但展示须转义，禁止作为命令或模板执行。

备份先暂停领取新任务，等待本地DB事务结束，用sqlite backup API生成一致副本；素材按hash清单复制，引用的私密登录态不进普通交付包。恢复先在新目录校验，不覆盖原库；所有未决外部attempt恢复后先reconcile。
