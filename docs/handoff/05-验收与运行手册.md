## 未来应用命令契约

以下命令需接手agent先实现相应任务。本包交付时执行会因应用尚未建设而失败，不把它们当已通过记录。

```powershell
# 在应用根目录；先按T02批准并准备依赖
python -m app.cli doctor
python -m app.cli init-db --data-dir runtime
python -m app.cli create-owner --data-dir runtime
python -m app.cli import-baseline --data-dir runtime --source docs/handoff/sources/strategy-20260914
python -m app.cli verify-baseline --data-dir runtime
python -m pytest tests/unit tests/integration -q
```

预期：doctor列出实际组件与缺项；init-db可重复执行且不清数据；create-owner交互输入密码（不经命令行参数）；导入报告30机会、0伪造商品、重复跳过；verify-baseline分别报告原始行和可算规则差异；pytest全部通过。缺依赖时先处理批准，不让脚本自动pip安装。

T24之后：`powershell -NoProfile -File scripts/start.ps1`，本人打开`http://127.0.0.1:8510`登录。start分别启动web/worker并存PID，重复启动不重复进程。`powershell -NoProfile -File scripts/stop.ps1`只结束本app进程，保留数据。若已有端口占用，显示原因，不杀陌生进程。

worker命令契约：`python -m app.worker --data-dir runtime`；web使用已配置的data_dir启动app.main中的app，默认端口8510。脚本统一传入APP_DATA_DIR的解析后绝对路径，防web/worker打开不同数据库。

备份命令：`python -m app.cli backup --data-dir runtime --output work/backup-check`；恢复命令：`python -m app.cli restore --backup work/backup-check --data-dir work/restore-check`。目标存在且非空则拒绝，不能覆盖。恢复后先核对未决attempt再允许执行。所有命令失败必须非0退出码。

## 第一件真实商品怎么验收

从有明确规格和货源的宠物商品开始；历史30词只是线索。读取实际商品/供应信息，确认成本及平台字段，先完成只读证据G3。图视频收费部分逐笔形成可审方案；确认后生成，再由用户检查成片/套图。上架/发布前查看具体账号、标题、价格、库存、素材版本并确认。保存实际回执达到G4。

经营验证先确定观察窗口和目标，结果未到时显示待观察。达到窗口仍样本不足就是不足；可产出执行复盘，但不冒充商品验证完成G5。真实接口不可用时可输出人工执行包并等待回执，明确自动化部分未验收。

## 故障处理

| 现象 | 必须采取的动作 |
|---|---|
| 登录失效/验证码 | 等本人处理；保留job和输入，不循环点登录 |
| 付费额度/报价不明 | 停该调用，列未知和上限缺口；可继续免费部分 |
| 收费或发布超时 | 标UNKNOWN，查provider id/平台记录，不自动重发 |
| 用户撤销但已提交 | 展示已提交事实；查询结果；取消是否可用据实际供应商能力 |
| 网页字段变了 | 能力降级，保存失败证据；禁止把缺字段写成0 |
| 图片与实物不符 | 标不可用并关联原因；新版本重新审查，收费重做另批 |
| worker异常退出 | 纯计算租约过期可恢复；外部attempt先核对 |
| 手机打不开 | 检查电脑运行与同局域网、本人登录/传输保护；不买服务器或自动开公网 |
| 没有足量经营数据 | 输出缺口与待观察，不训练/校准成既定结论 |
