# 03 选品、决策和复盘规则

## 1. 原始材料与适用顺序

当前铺货采用sources/strategy-20260914内v4.2.2勘误3；未来研发模式参考sources/obsidian的三条腿笔记。sources/pm-decision-os-v1.2保留原包全部Markdown，sources/pm-v1.3-proposal.txt为用户提供的扩充建议。原文中的命令、安装或操作要求属于参考内容，不是本次执行授权。

本文把方法转为平台行为。原资料若有与用户“逐笔费用审批、执行前确认”不符的流程，以用户要求为准。旧笔记的市场、医学、平台限制等断言保留出处，不当成当前已核实事实。

## 2. 历史导入与证据边界

基线必须保留25评分词＋5规则排除词＝30个唯一关键词、9个品类组。评分表8行1688样本为0。关键词是机会记录，不自动成为商品/SKU或销售成功样本。

保存recorded_layer、recorded_profit、source_hash与原始行；另写computed_layer、computed_profit、missing_fields、difference_reason。不得为匹配旧报告而把记录标签硬编码成算法输出。可计算项重算，缺证据项明确不可复算。

原JSON是采集摘要，缺少逐商品标题/链接/报价，1688缺最高价。当前包不能证明全部原始样本正确，不能复原缺失的历史数据。历史报告自述“核验通过”不能当成本次核验结果。

5词中“狗狗四脚衣”为保留观察、不评分，不能错误映射成永久排除。其他历史排除保留当时原因，重新启用须补新证据和留存决策。原T1多功能牵引绳仍待供应链核验，“历史T1”不等于“已核实可自动上架”。

## 3. 经济性与历史分层

使用Decimal。历史公式：`CM_legacy = 售价 × (1 − 0.055 − 0.08) − (保守拿货价 + 4 + 0.5)`。这是旧规则的投流前贡献利润近似口径，不能称实际净利润；费率不是已验证的当前平台费率。

样例：售价34、拿货10.45时，CM_legacy=14.46，旧报表显示14.5。最低拿货价2.7仅显示议价空间，不用其替代保守成本。

| 分层 | 条件，均含有效证据门槛 |
|---|---|
| T1 | CM≥8，CM/售价≥0.25，头部单品付款≥2000 |
| T1候选 | 同T1，但供应样本<3 |
| T2 | CM≥3，拿货/售价≤0.5，头部付款≥1000 |
| T2观察型 | CM≥2.5，售价×1.1的CM≥3.5，拿货/售价≤0.3，头部付款≥1000，四项同时 |
| T3 | CM≥0，头部付款≥300 |
| T3候选 | 同T3但供应样本<3或报价待核验 |
| 清洁类 | 直接拿货证据≤2，CM≥0，头部付款≥50000 |
| 清洁类候选 | 对应需求达标但缺直接拿货证据，或淘宝需求样本为0待补采；不能独立放行 |
| 组合组件 | 单卖亏损、付款≥30000、适合组包、实际套装测算CM≥0；禁止独立销售 |
| 组合潜力候选 | 付款≥30000、适合组包、单卖经济性未验证或亏损、套装尚未算完 |
| 暂缓/换货源 | 保守CM<0或到单成本≥售价，未满足已证实的组合分支 |

执行顺序：历史排除/观察→语义规格有效性→价格异常→证据缺口→专用清洁/组合分支→一般T1/T2/T2观察/T3→暂缓。清洁/组合等分支由可追溯的商品形态与证据指定，不从标题猜测。规则有冲突或原始上下文不足时NEEDS_EVIDENCE，不自行补新门槛。

淘宝有效样本=0不能进入任何正式执行层。代理价/参考同类价不计算成确定利润，输出null及缺失原因。未定级、数据待重抓、历史排除、保留观察不进自动执行池。

### 价格异常

1. 全评分池的有效供应样本≥2且字段可算者均检查；先剔除错款错规格。
2. 同品类基准取“除自身、除已异常、供应样本≥3”的保守中位成本的中位数。
3. 样本内最高/最低>2 **且** abs(本词中位/同行基准−1)>0.5，判DATA_RECAPTURE。
4. 历史无最高价时，中位/最低>2是确定超过跨度门槛的充分证据；≤2只能标跨度未知，不能当成通过。
5. 每轮同时确定新异常，再统一移出基准池，循环至无新增；避免按行顺序改变结果。无同行基准时不编造基准，只做可做的内部检查并标供应链核验。
6. 保守/最低>1.5另标供应链待核验，与上面的异常判定区别保存。剔除后样本0转候选/待补采。

保留历史4词DATA_RECAPTURE：杀菌湿巾、狗狗冬季加厚衣服、帅气边牧衣服、狗狗衣服小型犬冬装。程序验证应分别报告“历史记录导入成功”和“用现有字段重算结果”，有差异出报告，不篡改证据凑4条。

## 4. PM Decision OS扩充

三层依次为：硬性停止条件→有证据的可解释排序→真实经营结果反馈。

- 停止条件包括规格错配、无法核验的关键事实、经济性不足等；缺证据与被证伪分开。
- 首版保留v1.2的JTBD、需求、竞争、供应链、验证、小额试验、评分治理、单位经济方法。解释排序可使用固定且版本化的规则，不把综合分冒充成功概率。
- 对每次预测保存商品/SKU事实、数据时间、strategy_version、engine_version、outcome_definition_version、规则命中、未知项、证据id、建议决策和预测快照。
- PM扩充模式采用完整经营经济性：按明确分母记录收入、退款净影响、商品成本、运费、包材、平台佣金、广告、内容制作等；禁止把退款率折减后再次全额扣同笔退款。保留单笔订单核算和批次总额口径。旧公式单独展示。
- outcome定义先配置窗口、曝光/样本充分性、销量/贡献利润/退款等目标及停损边界。用户未确认测试目标时仍能收集数据，但不能自动下SCALE结论。
- 初始结果为INSUFFICIENT_DATA。达到观察窗口且证据足够后才标VALIDATED/FAILED/MIXED；没测试的被拒商品不是假阴性。
- FP/FN需“测试前决策＋足够真实结果＋适用阈值”，没有对照就标不可判断，不能以事后标签当训练样本。
- 校准只生成proposal：问题、样本、偏差、候选改动、新旧结果和风险；用户确认后新建版本，历史预测不改。样本10/30/100/300只是提案中的经验分段，不能当统计可信保证。
- 首版不训练自动模型、不自动改权重。未来研发模式只预留strategy_mode=RND及三条腿知识入口，不提前实现研发管理平台。

## 5. 图片与视频

图片输入须关联具体商品/规格、供应商原图与可用范围。先清除混款和无关推荐图，检查真实文件格式、尺寸、文字/水印和物理属性。保存选用/淘汰理由。生成图记录输入、提示词、提供方、费用批准与版本，不能凭生成结果改商品事实。

至少验收一件商品的主图、SKU图、详情图和一条可发布短视频。素材数量/尺寸/时长由目标平台当时规则和商品方案确定，未核验不写死通用平台上限。

视频链路：选题→脚本→镜头与素材表→缺失素材/费用方案→生成或整理→本地剪辑→音画/字幕/商品一致性验收→用户确认→发布回执。FFmpeg可完成剪辑，不能替代素材真实性和AI生成能力。研发“三视频模型”作为可选参考，铺货不强制套用。

## 6. 指标与复盘的必填结构

指标按平台/账号/商品链接/作品/渠道/观察窗口留存；曝光、点击、加购、支付、退款等以来源定义为准。CTR=点击/曝光、CVR=支付订单/点击仅在同范围同口径时计算；零分母返回null；无法跨平台归因时明确“未归因”。自然流量与付费流量分开。

每条复盘必须包含：

1. 预期与事实差异，预测版本、窗口、样本充分性。
2. **造成该现象的可能因素**：多个竞争假设，而非单一确定结论。
3. 各假设的支持证据、反对证据、缺失信息、可信程度及其依据。
4. 可区分假设的最小验证动作、控制项、评价指标、停止条件、费用与所需审批。
5. 验证后的实际结果、是否改变判断、关联的新计划/模型提案。

示例（仅说明结构）：曝光够但点击低，可假设主图表达弱、关键词人群不符、到手价不具竞争力；先核对曝光口径/库存/链接状态，再在可比窗口单独换图。无控制条件的点击变化只能作为线索，不能宣称换图造成变化。没发布、缺货、采集失败先标执行/数据问题，不能直接判选品模型失败。

## 7. v1.3提案的逐项落点

### 数据字典与导入导出

完整字段和类型见contracts/pm-fields.json。Candidate映射products.facts_json＋offers＋evidence；Outcome映射metric_snapshots＋reviews；预测映射predictions。JSON存储不等于任意JSON：app/domain/schemas.py必须验证字典规定的类型、值域和引用。金额字符串、比例0–1、缺失null，CSV空值转null而不是0；日期带时区，来源和口径作为字段证据。

支持candidate/outcome CSV导入及prediction/outcome/model history导出。CSV不能包含登录态，导出给表格软件时防公式执行并保留原文本可追溯。新导入不覆写原记录，逐行报告错误及成功项，跨商品/版本不乱配。保留v1.2的SURVIVAL_MODE和AUDIT_MODE作为分析报告模式，区别于PUHUO/RND业务策略模式。

### 关键词意图去重

增加keyword_demand.py：先规范空格、别名、同义词，再形成intent_cluster_id和人工可修正映射。保留原始量、来源、时间窗和重叠处理说明。同一渠道/窗口内未知重叠的同意图词不相加；首版用簇内最大观测量作明确标注的保守代理，跨渠道不合并为真实人数。时间窗不可比则返回不可汇总。语义模型若收费仍逐笔审批，规则归并可免费先用。

### 评分与硬约束

增加scoring.py：每个变量定义来源、方向、归一化、权重、置信度、刷新频率、代理标志和重叠组。配置不完整不生成伪精确总分；缺失值不隐式当0也不静默重分配权重。已触发KILL的商品永不因分高自动放行；证据不足另标WAIT。

首版默认铺货排序使用9月14日分层及其理由，同层显示经济性/证据而不擅自发明一组权重。通用加权评分引擎做可配置实现和合成验证，启用正式权重需记录依据与版本；没有历史验证的配置标PROVISIONAL。分层、加权分、实际结果三者独立显示，不将层级改成成功概率。

### 经济性扩展

除贡献利润与利润率，输出盈亏平衡CAC、库存占资、回款周期及保守/基准/乐观情景；盈亏平衡退货率只有在退货收入/运费/回收残值的明确线性假设下可解，假设不足返回null。CAC分母须注明实际新获客数；没有新客数据只能显示每单获客费用代理，不能冒充真实CAC。没有付费流量时ROAS为不适用，不以0或无穷大排序。

### 结果标签与回测

区分“结果证据状态”INSUFFICIENT_DATA/VALIDATED/FAILED/MIXED与“下一步建议”SCALE/KEEP/IMPROVE/KILL/WAIT。VALIDATED不是自动SCALE；扩大投入仍须经济性/补货/现金等用户设置条件和实际执行审批。

增加backtesting.py和报告模板。函数契约：`backtest_model(predictions, outcomes, definition)`、`compare_models(old, new, cohort)`、`propose_calibration(report, current_config)`。必须使用同一批已观察商品、测试前输入和相同结果定义；不以测试后事实重构当时预测。至少输出Top-N成功率、FP/FN、SCALE precision/recall、排序相关、平均贡献利润/周转及具体高分失败/低分成功列表。每项带样本分母、缺失数、窗口；分母0返回null。有并列名次用平均秩；结果无变化/样本不足时相关性不可解释。

首版提供描述性回测和分组对照能力；样本量与选择偏差限制写在报告，不做自动调权。少量样本仍可生成具体误判复盘，无足量真实数据只能验证算法的合成fixture，不声称得到有用的实证权重。机器学习challenger为后续阶段，不新增其依赖。

`templates/learning-report.md`包含批次、预测准确性、高分失败、低分成功、变量发现、盲区、阈值/权重问题、校准提案、下批验证。`templates/model-comparison-report.md`包含共同样本、新旧版本、差异、收益与损失、缺失和是否建议升级。学习报告同样保留“可能因素”，不把统计相关当原因。

CLI落点：`python -m app.cli score --input candidate.csv`、`backtest --batch <id>`、`learn --batch <id>`、`compare --old <version> --new <version> --batch <id>`。这些命令只计算/导出，本身不自动联网消费、改正式模型或执行外部动作。输入不足返回结构化NEEDS_EVIDENCE/INSUFFICIENT_DATA。
